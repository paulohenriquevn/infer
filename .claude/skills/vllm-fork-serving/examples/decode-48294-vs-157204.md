# Decode on two "identical" hosts: 157204 against 48294

The same offer type (4x RTX PRO 6000 on Vast.ai), image, checkpoint, script (`bench/server-vllm-dcp1-direct.sh`) and harness, one day apart. Host 48294 decoded up to 5 times slower. This is why every host passes the C32 gate before its numbers count.

Sources (Observed, `llm-inference-bench` 0.8.0 `decode.json`, context 0, 30 s per cell, one run per host):

- 157204: `f3/resultados/vast-20261111/vllm/vast-vllm-dcp1/decode.json`, 2026-11-12 00:2x.
- 48294: `f3/resultados/vast-20261112/vllm/vast-vllm-dcp1-rep/decode.json`, 2026-11-12 10:xx.

## Hardware during the run

From `hardware_run_summary` in each `decode.json` (sampled over about 166 s):

| Field | 157204 | 48294 |
|---|---|---|
| `gpu_util_avg_pct` | 90.69 | 90.75 |
| `mem_util_avg_pct` | 47.07 | 17.95 |
| `power_total_avg_w` | 986.56 | 661.89 |
| `temp_avg_c` | 52.06 | 33.52 |
| `pcie_rx_avg_mb_s` | 10,768.28 | 4,625.46 |
| `vram_used_avg_pct` | 97.44 | 97.47 |

How to read it (Inferred): the GPUs report the same "utilization" (a kernel was resident) but on 48294 their memory controllers were busy 38% as often (17.95 against 47.07), they drew two thirds of the power and ran 18.5 °C cooler on average. The GPUs spent more of their time waiting than computing. Throughput stops scaling after C8 and falls at C32, which fits a shared bottleneck outside the GPU (CPU launch, host memory, PCIe path or all-reduce) rather than a slow GPU. Which one is Unknown; candidates are in `../references/troubleshooting.md` section 1.

## The gate this produced

```text
C32 aggregate decode with the DCP1 profile, about 5 minutes after the server is up:
  >= 1,400 tok/s  -> host qualifies
  <  1,400 tok/s  -> discard the host; its numbers do not count
```

Source: `docs/06-aws-implementation-plan.md` phase 1 and `ARQUITETURA.md §29.10`. The threshold applies to DCP1 only: DCP4 gave 1,279 and 1,288 at C32 on the good host (`vast-vllm-r1`, `vast-vllm-r1-rep2`). It was set from two hosts; treat it as a starting rule and revise it with AWS data.
